# 책 기반 Agent 개선 — 이어서 시작하기

마지막 갱신: 2026-10-07 (KST)

## 목표와 진행 방식

『Build an AI Agent (From Scratch)』를 참고하며 현재 프로젝트를 개선하고, 결과를 포트폴리오에 반영한다.

사용자 우선순위(2026-10-07): **프로젝트를 빨리 진척시켜 포트폴리오에 반영하고, 공부는 작업에 필요한 부분만 한다.**
`/study-session` 방식은 시간이 오래 걸려 이 트랙에서는 쓰지 않는다(사용자가 요청할 때만).

사용자 우선순위(2026-10-01): **기존 자동 리포트 개선을 먼저 진행하고, 대시보드의 대화형 기능은 후속 확장으로 둔다.**
현재 작업 범위에 챗봇 UI·대화 메모리·대화용 도구 호출은 포함하지 않는다.
자동 리포트의 고정 워크플로는 유지하며, 필요한 경우 특정 분석 단계에 제한된 자율성을 추가할 수 있다.
챗봇은 인터페이스이고, 에이전트 여부는 모델이 도구와 다음 행동을 선택하는 실행 구조로 구분한다.

**빠른 모드:** 작업 시작 → 필요한 개념 1~3개를 5분 설명(책 쪽수는 선택 참고) → 짧은 설계 합의 → 구현·테스트 → 포트폴리오 산출물·면접용 3문답.
독서 완독은 진행 조건이 아니다. 2026-10-06까지의 독서 우선 흐름은 [누적 기록](LEARNING_LOG.md)에 남아 있다.

## 전체 계획과 현재 검토 지점

[ROADMAP.md](ROADMAP.md)가 전체 계획의 기준이다. 이 파일에는 상세 설계를 중복하지 않는다.

- 합의한 순서: R1 뉴스 도구 반환 → **E1 기준 평가셋·트레이싱**(2026-10-06 추가) → R2 기사 근거 확보 → R3 리포트 개선 → R4 추가 조사·평가 → R5 대화형 확장.
- R1은 2026-10-06 완료했다(커밋 `de1b681`, push 전). 완료 근거는 [ROADMAP.md](ROADMAP.md) §4 체크리스트·검증 결과, 실행 순서와 코드는 [R1-PLAN.md](R1-PLAN.md)에 있다.
- 다음 구현 대상은 E1이다. 범위·원칙은 [ROADMAP.md](ROADMAP.md) §5. 고정 사건 10건 내외 + 도구 응답 스냅샷 + 정확 일치 채점(라우팅·`recommended_action`)으로 현재 코드의 기준 점수를 반복 실행 범위와 함께 기록하고, LangSmith 트레이싱을 켜고 끌 수 있게 한다.
  GAIA 문제 자체는 쓰지 않고(입출력 구조가 다름) GAIA의 성질(명확한 정답·난이도 단계·같은 세트 반복)만 가져온다.
- 그다음 R2 기사 근거 확보. 착수 전에 본문 확보 방식(공급자 제공 정보·HTTP 추출·브라우저)과 검색·읽기 도구 경계를 세부 설계하고, 완료 후 E1 세트로 전후 비교한다.
- 일반 웹 검색은 R4 후보로 둔다. R1의 시도 로그로 SerpAPI `empty` 빈도를 볼 수 있게 됐다.
- R2 이후는 각 단계에 도달했을 때 세부 설계한다.
- 문서 구조 승인과 제품 구현 완료를 구분한다. 기존 퀴즈·독서 완료 확인을 다시 시작하지 않는다.

## 기록 규칙

- **이 파일:** 현재 위치와 다음 행동만 갱신한다.
- **[ROADMAP.md](ROADMAP.md):** 단계 상태·완료 기준·검증 근거를 갱신한다.
- **[LEARNING_LOG.md](LEARNING_LOG.md):** 사용자 결정·교정, 설계 결정과 이유, 변경 파일·실제 검증 결과를 날짜별로 덧붙인다.
  세션당 3~5줄로 짧게 쓴다. 에이전트가 기록하며 별도 양식 작성은 요구하지 않는다.
- 매 세션 종료 또는 중요한 진도·결정 변경 시 기록한다. 읽음·설명을 들음·독립 적용·구현·검증은 구분한다.
- 과거 기록의 회상·전이 “미확인”은 관찰 이력일 뿐, 다음 독서나 적용을 막는 미완료 과제가 아니다.
- 이전 대화의 **검색 3회는 예시**이며 실제 정책이 아니다. 설계 후보를 구현 확정으로 취급하지 않는다.
- 기존 LangGraph Lab 진도는 [LAB-PROGRESS.md](../langgraph-labs/LAB-PROGRESS.md)를 따른다.
  다른 트랙의 진도를 덮어쓰거나 같은 기록을 중복 생성하지 않는다.
- Python 실행은 `uv run`, 테스트는 `uv run pytest`로 한다(2026-10-07부터 uv로 의존성 관리, `testpaths`로 `tests/`만 수집). `scratch/` 경로는 직접 주지 않는다.
